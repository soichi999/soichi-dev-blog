個人開発中のパズルゲーム『てるてるメガネ』には、ランダムに作られる地下の階を、どこまで潜れるかを競うモード「BF」があります。この記事では、その盤面生成が重くなった問題を、**次の階を別スレッドで先に作っておく**ことで解決した方法をメモします。

<TeruruTalk text="地下の階は、ぼくが入るたびに新しく作られるんだ。" />

## 問題: 深い階ほど生成に時間がかかる

BFの盤面は、ルールを満たすまで作り直す方式で生成しています。

- 解ける(エレベーターまで行ける)
- 刺さる可能性のある針が、決まった本数以上ある
- 鍵の数が、部屋の広さに見合っている

深い階ほど条件が厳しくなるので、作り直しの回数が増えます。1枚の生成は平均0.4秒ですが、深い階では最大3.6秒ほどかかり、その間ゲームが止まっていました。

## 方針: 今の階を遊んでいる間に、次の階を作る

プレイヤーは1つの階を、少なくとも数秒は遊びます。そこで、今の階を作り終えたら、**次の階の盤面をすぐ別スレッドで作り始める**ようにしました。

```csharp
using System.Threading.Tasks;

Task<StageData> _prefetch;
int _prefetchDepth;

void StartPrefetch(int nextDepth, GeneratorSettings settings)
{
    _prefetchDepth = nextDepth;
    // Unityのオブジェクトに触らない、純粋な計算だけを別スレッドへ
    _prefetch = Task.Run(() => StageGenerator.Generate(nextDepth, settings));
}

StageData TakePrefetch(int depth)
{
    if (_prefetch != null && _prefetch.IsCompleted && !_prefetch.IsFaulted && _prefetchDepth == depth)
    {
        var data = _prefetch.Result;
        _prefetch = null;
        return data;
    }
    return null; // 無ければ、今までどおりその場で作る
}
```

次の階に入るときに先読みの結果があれば、それを使います。まだ終わっていない、または深さが合わないときは、今までどおりその場で作ります。

## 注意点1: Unityのオブジェクトは別スレッドで触れない

`Transform`、`Tilemap`、`Resources.Load` などのUnityのAPIは、メインスレッドでしか使えません。別スレッドでは、**マス目の配列を作るところまで**にとどめ、Tilemapに塗るのは、メインスレッドに戻ってから行います。

生成の設定をインスペクターで持っている場合は、その値を普通のクラスに写してから渡します。`MonoBehaviour` を別スレッドで直接読むのは避けました。

## 注意点2: 代わりの盤面の読み込み

作り直しに何度も失敗したときのために、あらかじめ用意した「代わりの盤面」を読み込む仕組みがありました。これは `Resources.Load` を使うので、別スレッドでは動きません。

そこで、先読みのときは代わりの盤面に頼らない設定にしました。失敗したら先読みの結果を「無し」にして、メインスレッドでその場で作る、いつもの流れに任せています。

<TeruruTalk text="次の階は、もう用意できてるよ。待たずに、どんどん潜っていこう！" />

## まとめ

- 重い生成は、プレイヤーが遊んでいる間に別スレッドで先に作る
- 別スレッドでは純粋な計算だけ。Unityのオブジェクトにはメインスレッドで触る
- 先読みが間に合わない、失敗したときは、今までの作り方に戻る
